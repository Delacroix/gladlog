# Predicate Index

**English** · [中文](predicate-index.zh-CN.md)

The place to look up "does this fact already have a predicate?" — before you write a constant, a threshold, a tolerance, a sampler, or a formatter.

## Why this page exists

`CLAUDE.md`'s first hard rule is the **shared-predicate rule**: analysis code (`packages/analysis`) and the verification gates (`packages/eval`) must decide **the same fact** with **the same predicate** — same constant, same sampling function, same tolerance — anchored on the _rendered_ value, because the gates re-parse the rendered prompt text. The rule also states the remedy: export the predicate in one place and import it on both sides; when that is impossible, write a unit test that asserts equality — do not rely on a comment.

The historical cost of breaking it: in the 2026-07 full-corpus audit, **five independent bugs were all this one class** — inconsistent HP sample radius, bounded vs unbounded backtracking, interpolated vs raw vs off-instant sampling for line of sight, and fractional seconds vs the rendered-second scan grid.

The rule was never the missing piece. On 2026-08-01 the same person, having read the rule, re-implemented two predicates by hand inside a single day's work: the "match already known" test was copied into the orchestration shell, and `dateKey` formatting was written out a second time in another file. **What was missing is an index** — somewhere to see, before writing new code, that the fact already has an owner.

## How to use it

**Before writing new code.** Search the table for the _fact_, in words — not for a symbol name you half-remember. If the fact is listed, import the predicate. Do not re-derive it, do not copy the literal, do not inline "just this once" a regex that already exists.

**When you add an "analysis asserts X, the gate verifies X" pair:**

1. Export the predicate from one module and import it on both sides.
2. Add a row to the index below — in **both** language versions.
3. Add the same row to `packages/eval/test/predicateIndex.test.ts`. That test parses this page, so the page and the test cannot rot apart.
4. If sharing the export is genuinely impossible — the other side is a markdown spec, a rendered string, or a different language — add an equality assertion to that same test. That is CLAUDE.md's explicit fallback, and a comment is not a substitute for it. `FACT_AUDIT_MIN` / `FACT_AUDIT_MAX` below is the worked example.

**When you rename or delete a predicate.** The test imports every symbol listed here, by file path. A rename breaks CI; update this page in both languages instead of deleting the row.

## Reading the table

- **Fact** — what gets decided, in words. This is the column to search.
- **Authoritative predicate** — `file` → `export`. Exactly one per fact.
- **Consumed by** — notable call sites, not an exhaustive list. "gate" means `packages/eval`.
- **Notes** — the semantics that are easy to get wrong.

Paths are relative to the repository root. Everything under `packages/analysis/src` can be imported by file path; most of it is also re-exported from the package root (`@gladlog/analysis`), but `factFormat.ts`, `spellCategories.ts`'s `isCastBlockingAuraType` and a few others are reachable only by file path.

## Not yet unified

Real duplicates found while compiling this page (2026-08-01). Recorded, **not** fixed — fixing them is separate work.

1. **The "healer trained" distance (8 yd) is declared twice, both private.** `packages/analysis/src/utils/positionAnalysis.ts` `HEALER_TRAINED_YARDS` produces and renders the claim; `packages/eval/src/quality/positioningScan.ts` `TRAINED_MAX_YARDS` is the gate that verifies it. Same value today, no import, no equality test — the exact shape the rule forbids.
2. **"Maximum plausible CC range" is three different numbers.** Gate `positioningScan.ts` `IMPOSSIBLE_CC_YARDS = 50`; `ccTrinketAnalysis.ts` `CC_MAX_PLAUSIBLE_RANGE_YARDS = 45`; `healerExposureAnalysis.ts` `MAX_CC_RANGE_YARDS = 40`. All private. The gate's cap is deliberately the loosest, but nothing pins the ordering.
3. **"Closest distance in a window" is sampled differently by producer and gate.** `positionAnalysis.ts` walks whole seconds with `INTERP_MAX_GAP_MS` (1500 ms); `positioningScan.ts`'s `minDistanceInWindow` walks whole seconds _plus_ every advanced-action timestamp _plus_ a 250 ms grid, with `LOS_SWEEP_GAP_MS` (3000 ms). Same fact, different sampler and different tolerance; the gate compensates with a deliberately one-sided test.
4. **`makeRng` is implemented twice inside `packages/eval`.** Exported from `ab/abCompareStats.ts`, and copied private into `judge/buildCalibrationSuite.ts` with a comment saying it matches. Should be an import.
5. **`IndexEntry` is declared five times in `packages/eval`.** Authoritative in `corpus/buildCorpus.ts` — the only named declaration carrying `ownerName` — plus `quality/promptQualityCheck.ts`, `ab/blindAbPool.ts`, `judge/buildCalibrationSuite.ts`, and an inline shape in `scripts/positioningScan.ts` that re-adds `ownerName` by hand.

Not duplicates — recorded so nobody "unifies" them by mistake:

- `HP_AGREEMENT_TOLERANCE_PP` (3 pp) in `promptQualityCheck.ts` is gate-only slack over rendered text. It has no analysis-side counterpart and must not be equated with `HP_SAMPLE_RADIUS_MS`.
- `quality/coverageManifest.ts` deliberately refuses to share the analysis pipeline: sharing it would make the check circular. It shares only static tables (`ccSpellIds`, `trinketSpellIds`, `getEnglishSpellName`, `specToString`).

## Keeping this page honest

`packages/eval/test/predicateIndex.test.ts` is the executable half of this page. It

- imports every predicate listed above by its file path and fails if any is missing or renamed;
- parses the table out of both language versions and fails if they list different predicates, or if either disagrees with the test's own list;
- asserts the pairs that cannot share an export: that the gate's LoS tolerances are still _derived_ from the analysis exports rather than re-typed as literals, and that `matchDateKey` still formats through `dateKeyOf`;
- asserts the two producer/gate inverses end to end — a window rendered through `fmtTime` + `renderedWindowSeconds` passes `checkWindowSpanConsistency`, and percentiles taken from `toSortedFinite` pass `checkPercentileMonotonicity` — each with a negative control, so the assertion cannot pass vacuously.

Run it with `npm test --workspace=packages/eval`.

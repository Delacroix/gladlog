# AI Analysis Inline Spell Icons (backlog #15) Design

2026-07-28 · Source: Bilibili user feedback ("AI says your normal Tranquility is useless, I still have to guess the English").
Other views of the report all use icons, only the AI-generated narrative/findings/deep dive text are plain text English spell names,
Chinese users have to guess.

## Goals and Criteria

In `zh` response mode, known English spell names in finding cards (title/explanation/deep dive text) and comparison commentary
are rendered as "icon + Chinese name" inline components, hover to reveal the original English name; class/spec names follow suit.
In `en` response mode, only insert icons, do not replace names (already approved). Stored text/prompt/audit chain/exports have zero changes.

## Decision Record (brainstorm approved)

1. **Dictionary Scope**: Full set of spells with icons (same set as `SPELL_ICONS_GENERATED`, ~42k entries).
2. **EN Mode**: Only add icons, do not replace names.
3. **Replacement Exits**: Finding card three fields (FindingsList + KeyMomentAxis two renderers),
   comparison commentary `result.report`, class/spec names, and conveniently add icons to KeyMomentAxis chips.
4. **Route**: Renderer layer post-processing (Plan A). Vetoed: write back to storage (cache bifurcation, breaks audit trust chain),
   prompt outputting Chinese directly (audit chain is anchored by English names, would require full chain rewrite).

## Architecture

### Data Layer (packages/analysis)

- **New datagen artifact `spellNamesZhGenerated.json`**: wago.tools `SpellName` table
  `zhCN` locale, filtered to the id set with icons, estimated 1-2MB. Build config continues to use
  `json: { stringify: true }` (large JSON lesson, see closed backlog items).
  `datagen-manifest.json` registers entry count and byte size; `writeManifest.ts` syncs.
  ⚠ Implementation step one: first test the `zhCN` locale parameter of the wago CSV API; if not supported, switch to
  `Name_lang` multi-locale download method, if that fails downgrade to "only major CD manual table" and report back.
- **English name → id inverted index**: Lazily built at runtime (not written to disk), inverted from existing `spellNames.json`,
  only including ids with icons. Same-name multiple-id resolution order: **spellId observed in this match >
  `observedSpellIdsGenerated` > smallest id**.
- **Class/Spec shared table**: `SPEC_NAMES_ZH` floats up from `ProComparisonVerified.tsx` to
  shared module, adding "English spec phrase → specId + Chinese name"; icons use the existing
  `specIconUrl(specId)` (CDN precedent same as arena minimap, visual tests covered by stubExternal).

### Renderer Layer (packages/desktop renderer)

- `report/derive/inlineRich.tsx`: Pure function
  `renderRichText(text, { matchSpellIds, lang }) → ReactNode[]`.
  - Longest match priority (names sorted by length descending and compiled once into an alternation pattern), preventing "Ice Block" from being
    intercepted by "Block"; JS `\b` naturally forms boundaries for CJK/Latin adjacency.
  - `zh` mode: Hit → `<SpellInline>` (icon + display name); display name priority:
    **Match log name > zh dictionary > original English** ("skills not cast this match" is exactly the reason
    the dictionary exists, e.g., Tranquility is useless).
  - `en` mode: Hit → icon + original English, no name replacement.
- `<SpellInline>` component: Reuses `SpellIcon` (IPC + disk cache, size 14),
  `title` = original English name (reconciliation anchor).
- Integration points (6 places): `FindingsList` and `KeyMomentAxis`'s title/explanation/
  deepDive.text; `ProComparisonVerified`'s `result.report`.
  Conveniently: KeyMomentAxis deep dive chips get `ChipIcon` added (aligning with FindingsList, including the existing comment convention for empty label
  to prevent fallback character duplication).

## Boundaries (Intentionally Not Doing)

- Do not touch storage/export/audit/faithfulness gates —— replacement is pure display, hovering English name ensures reconciliation with
  raw events and export Markdown.
- Do not do click jump, skill tooltip details (YAGNI).
- `candidateShortLabel` and other deterministic short labels, MistakesCard text are not in this phase (they are not
  model outputs; if they also need replacement, just reuse the same `renderRichText`, open a separate small ticket).

## Testing

- `inlineRich` pure function unit tests: multi-word names ("Power Word: Shield"), same-name multi-id resolution
  (match-first), zh/en two modes, dictionary missing fallback (log name/English), CJK adjacency,
  no hit returns original.
- Component fixture tests: finding cards and comparison commentary render `<SpellInline>`; KeyMomentAxis
  chips show icons.
- datagen: transform function unit test (filter to icon set, entry lower bound assertion); manifest consistency.
- Visual baselines will change: **Generated by CI, absolutely do not run test:visual directly on local machine**.
- Before push: `npm test --workspace=packages/desktop && npm run typecheck &&
npx eslint packages/desktop/src --quiet`.

## Risks

| Risk | Mitigation |
| ---- | ---------- |
| wago zhCN locale unavailable | Implementation step one verification; fallback see Data Layer ⚠ |
| False replacement (English phrase collides with skill name) | Only include name set with icon ids + longest match; real false positive cases can add stop words |
| Dictionary volume regresses first screen | stringify load + lazy import (following spellEffectData precedent); performance budget gate covered by CI |
| Visual baselines bulk change | Expected, CI generates for human review |
